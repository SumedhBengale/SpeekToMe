# Validation scope

- x86 host: existing g6f.large, `GPU_HOST_IP`. Bootstrap ran with `EXISTING_NEMO=1`, `SKIP_NGINX=1`, separate gateway port 8190. Artifact downloads and checksums, packaged x86 runtime executable startup, authenticated admission and real ASR/diarization PCM/Ogg streams were checked. PC reached the gateway through an SSH tunnel. The existing NeMo model process/configuration remained the backend; this was not a clean x86 AMI boot or a numerical test of the converted F16 diarization model on x86.
- An earlier offline HTTP readiness attempt on the fractional L4 exhausted VRAM and restarted the existing model process. It recovered; readiness was changed to a short cache-aware streaming test. Successful checks recorded here happened after recovery. Production gateway/configuration were not replaced. The temporary x86 gateway, readiness timer and downloaded test assets were removed after testing; the original NeMo/gateway services were confirmed healthy.
- `x86-existing-runtime.json` contains the external functionality results, including independent 560 ms Opus chunks. All formats processed the intended 2.24 seconds and returned transcripts with speaker labels.
- Gateway `go test -race ./...` passed locally and on the existing server. Unit coverage includes auth before upstream access/upgrade, token stripping, admission and slot release, drain behavior, readiness rejection, Ogg page/message assembly and end granule preservation.
- `arm-builder.json`: T4G with the prebuilt CUDA 13.2/SM75 runtime and F16 diarization model passed verified-TLS public HTTPS/WS tests from the PC, including authenticated offline ASR, dedicated diarization, PCM, continuous Ogg and independent Opus chunks. Missing/wrong tokens returned 401. `arm-clean-boot.json`: a second g5g.xlarge Spot instance passed the same external checks using actual EC2 user-data and download-only bootstrap. Cloud-init finished with no errors at 17:43:01 UTC, after launch at 17:38:56 UTC (245 seconds). Termination of the build instance was requested; AWS last reported `shutting-down`. These tests do not establish p95 latency, safe production stream capacity, multispeaker diarization accuracy, or BF16/F16 numerical parity.

- `arm-after-reboot.json` and `reboot-services.txt`: automatic service restart, a new NeMo PID with matching readiness marker, TLS trust retained, token enforcement and PCM/continuous-Ogg/independent-Ogg inference all passed after EC2 reboot.
