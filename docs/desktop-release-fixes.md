# Desktop release fixes: issues 1–7

## Plan and implementation

1. **Exact recording playback.** Resolve server meeting ID to its immutable client UUID under the signed-in account, then check the local recording owner and canonical recordings directory. Reject ambiguous identities. Use an account-bound random playback ticket and a frontend generation guard so a late response cannot replace a newer selection.
2. **Capture buffer.** The old 12,000,000-sample raw buffer silently stopped accepting data after 125 seconds at 48 kHz stereo. Drain the native callback queue throughout capture. Streaming discards already-consumed raw samples. Batch retains only 16 kHz mono samples. Stateful fractional resampling preserves time across arbitrary callback boundaries, including 44.1 kHz. A five-second callback queue fails visibly if the consumer stalls. Dictation automatically submits at 30 minutes with a notification; this does not change the four-hour meeting limit.
3. **Private diagnostic content.** Desktop logging macros emit static event templates, never format runtime arguments. Frontend console messages omit dynamic arguments. The server privacy logger requires constant templates and renders only primitive numbers/booleans; text, errors, objects, provider responses, credentials and prompts are omitted. HTTP panic logging and the desktop panic hook also omit private details. Detailed meeting review dumps are removed. Source tests guard server logger imports and handler console writes. Worker error-log statements are sanitized as well. Functional API responses, encrypted history and local meeting data are not diagnostic logs and remain available.
4. **Durable meeting recovery and Quit.** Save and sync a per-meeting identity manifest before opening capture. Reject startup if metadata cannot be saved. Create private Ogg files, sync headers and directory entries before reporting readiness, write complete Ogg pages throughout capture and sync about once per second. Normal Quit keeps the event loop alive while the writer drains and syncs, then exits without waiting for network uploads. A 15-second emergency deadline handles a stuck driver. On restart, interrupted recordings are checked page by page with Ogg CRC validation; incomplete tails are trimmed, complete audio is preserved, and the existing idempotent upload queue resumes for the original account.
5. **Visible capture failures.** Surface missing devices, unsupported formats, callback errors, queue overruns, encoder failures, storage initialization and disk-write failures. A meeting observer stops both sources after failure, retains local audio and notifies the user; the Settings recording state receives the stop event. Windows system-audio startup now fails explicitly instead of silently continuing without the output track.
6. **Bounded playback memory.** Replace whole-file PCM vectors and Base64 IPC with one private temporary WAV on disk. Decode one packet at a time. If local audio is unavailable, download the authenticated cloud recording to a private temporary file and decode it there. A native loopback-only HTTP endpoint streams WAV byte ranges in 64 KiB reads. The webview receives only a random capability URL, bound to the current account; no API bearer token or filesystem path is exposed. Account changes invalidate reads; logout, Settings destruction and app restart clear the temporary playback cache. Playback failures appear beside the player.
7. **Preserve data on Windows uninstall.** Remove recursive profile deletion and credential deletion. The uninstall hook also forces Tauri's optional AppData-deletion flag off, so selecting the default uninstall checkbox cannot delete recordings or settings. Installed binaries and shortcuts remain managed by the normal installer.

## Practical limits

- Power loss can lose the latest approximately one second of audio plus device/OS/hardware buffering. Disk sync cannot guarantee preservation against defective hardware. Recovery processes the complete, verified portion; it cannot recreate samples never delivered by the device or persisted.
- Force Quit and the emergency shutdown deadline use restart recovery. Ordinary dictation is intentionally disposable when the app quits.
- Four-hour playback uses roughly 440 MiB of temporary WAV disk space, plus an Opus download for cloud playback. It no longer transfers that WAV as Base64 or loads it into a whole-file Rust PCM vector. Cloud playback waits for download/decode; progressive cloud playback is a separate improvement. Media-engine/OS caches still consume some memory.
- A damaged local recording can be downloaded from its encrypted cloud backup, where available. The original local files are never removed merely to clear playback cache.
- Existing logs written by previous versions are not retroactively sanitized. This change does not erase diagnostic archives, recordings or user profiles.
- Pending final-history save retries remain in memory, as documented in encrypted-personal-storage.md.

## Verification

Meaningful checks cover exact owner/identity matching, rapid meeting switching, 150-second stereo capture beyond the previous cutoff, arbitrary 44.1/48 kHz callback boundaries, interrupted Ogg pages, invalid-file preservation, private logging with sentinel content, bounded four-hour WAV reads, disk decoding, and installer profile preservation. The `--diagnose-playback` mode uses synthetic audio only to check the actual native webview's media loading and seeking. No microphone or user recording is needed for that diagnostic.

Verified on this checkout: 71 Rust desktop tests passed (clipboard mutation test excluded), Linux release build, Windows cross-compilation, server tests and race checks, frontend meeting-switch regression checks, installer preservation check, and three diarization admission tests. The actual Linux webview loaded a synthetic 90-second recording and sought to 75.5 seconds through the native HTTP endpoint. The macOS capture module passed an isolated Rust source/type check; native macOS runtime validation remains pending because the Tahoe VM was offline.
